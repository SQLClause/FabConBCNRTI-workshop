# How to export: ColdChainLakehouse

## Why this folder doesn't already contain the item definition

Fabric's `fab export` command produces a `.platform` file plus an item-definition
payload whose exact binary/JSON shape is generated by the service and is not
publicly specified as something safe to hand-author. Fabricating one here
without a live tenant to validate it against would risk silently breaking the
provisioning script for every attendee — the opposite of this workshop's
"fool proof" goal. Instead, the presenter creates the real item once by hand
in a dev tenant, then exports the tenant-verified definition into this folder
before the event. This is a one-time task, not something attendees repeat.

## Steps (do this once, in a dev/test tenant, ahead of the event)

1. Sign in to the Fabric portal and open (or create) a workspace to use as a
   scratch/dev workspace for building this template — it does **not** need to
   be named "Fabric IQ" (that name is reserved for the workspace the
   provisioning script creates live during the workshop).
2. In that workspace, select **+ New item > Lakehouse**, and name it exactly:
   ```
   ColdChainLakehouse
   ```
   (Exact name matters — the provisioning script's `setup/manifest.yaml` and
   every lab guide reference this literal name.)
3. Upload the three sample CSVs into the Lakehouse's **Files** section, into a
   `Files/SampleData/` folder:
   - `artifacts/SampleData/stores.csv`
   - `artifacts/SampleData/freezers.csv`
   - `artifacts/SampleData/customers.csv`
   (These are what `00_LoadReferenceData.Notebook` reads at run time — see
   `../Notebooks/HOW-TO-EXPORT.md`.)
4. You do **not** need to pre-create the `Customers`, `Stores`, `Freezers`
   Delta tables by hand — those are created by running the notebook after
   import (see the Notebook README and `setup/provision_fabric_iq.py`'s flow).
   Leaving the Lakehouse's **Tables** section empty at export time is expected
   and correct.
5. From your terminal, with the Fabric CLI installed and authenticated
   (`pip install ms-fabric-cli && fab auth login`), export the item definition:

   ```bash
   fab export "<dev-workspace-name>.Workspace/ColdChainLakehouse.Lakehouse" -o artifacts/Lakehouse/
   ```

   Replace `<dev-workspace-name>` with whatever you named your scratch
   workspace in step 1. Run this command from the repo root so the `-o` path
   resolves to this folder.
6. Confirm the exported files landed under
   `artifacts/Lakehouse/ColdChainLakehouse.Lakehouse/` (a `.platform` file and
   any item-definition files `fab export` produces for the Lakehouse type).
7. Commit the exported folder to git. From this point on,
   `setup/provision_fabric_iq.py` will `fab import` this real, tenant-verified
   definition into every attendee's workspace during the live event.

## Validate before the event

Re-run `setup/provision_fabric_iq.py --dry-run` (see `setup/README.md`) against
a second, throwaway workspace to confirm the exported definition imports
cleanly end to end. Do this within ~72 hours of the event per
`docs/risk-fallback-plan.md`, since preview/GA behavior for Fabric item types
can shift between releases.
